# 《深入设计模式》书评

> 书摘。原文用 > blockquote 引用，感想用普通段落。

## 章节定位

- 书：《深入设计模式》Dive Into Design Patterns
- 章节：全 23 个 GoF 模式 + SOLID 五原则 + OOP 基础 + UML 入门（总约 400 页）

## 原文摘录（用自己的话转述）

> 设计模式 = 对反复出现的设计问题的"可复用解决方案模板"，不是库也不是算法，而是"如何组织类与对象"的经验总结。
>
> 23 个模式按目的分三类：**创建型 5**（对象怎么造）、**结构型 7**（对象怎么组合）、**行为型 11**（对象怎么协作）。
>
> 用模式前先问："这是为了解决问题，还是为了显得聪明？"——过度使用模式是另一种坏味道。

## 全目录速览（模式 × 页码）

| 分类 | 模式 | 页码 |
|---|---|---|
| **创建型 5** | Factory Method / Abstract Factory / Builder / Prototype / Singleton | p.72 / 86 / 101 / 119 / 132 |
| **结构型 7** | Adapter / Bridge / Composite / **Decorator** / Facade / Flyweight / Proxy | p.143 / 155 / 169 / **181** / 198 / 207 / 219 |
| **行为型 11** | Chain of Responsibility / Command / Iterator / Mediator / Memento / Observer / State / Strategy / Template Method / Visitor | p.235 / 253 / 272 / 287 / 300 / 315 / 329 / 345 / 357 / 369 |

> 书中每个模式都含：**意图 → 问题 → 解决方案结构(UML) → 伪码 → 与相邻模式对比**。
>
> SOLID 五原则是模式的"上游"：先懂 S/O/L/I/D，再谈模式；模式是原则的落地工具。

## 我用自己的话说

这本书（Refactoring.Guru 中文版）是设计模式领域最友好的入门书之一，特点是：
1. **"问题驱动"而非"类图驱动"**：每个模式先讲一个具体痛点（如"子类爆炸"、"if-else 蔓延"），再引出模式，不堆概念。
2. **类比生动**：装饰器用"叠外套"、代理用"找人代买"、状态用"手机响铃模式"——记忆成本低。
3. **对比章节极有价值**：每个模式都配"与 X 模式的区别"，专治"这几个模式长得像"的困惑。
