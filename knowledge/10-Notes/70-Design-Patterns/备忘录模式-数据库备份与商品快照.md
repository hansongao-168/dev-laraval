# 备忘录模式（Memento）：数据库备份与商品快照

## 一句话

> **备忘录模式** = 把对象状态**快照**下来，之后能**恢复**到该状态，且不暴露内部结构。数据库备份（save/restore）和 Amazon 商品快照（record/diff/prune）都是 Memento 思想的生产级落地。

## 是什么

### 经典 Memento 三角色

```
Originator（原发器：要被备份的对象）
   ├── createMemento(): Memento    保存状态
   └── restore(memento)            恢复状态
Memento（备忘录：不可变快照）——只存状态，不暴露内部
Caretaker（管理者：保存/管理多个 Memento，但不改其内容）
```

### 落点 ①：数据库备份（`DatabaseBackupService` + `DatabaseRestore`）

- **Originator** = 数据库（要被保护的系统状态）
- **Memento** = 备份文件（`backup()` 用 mysqldump 生成快照文件）
- **Caretaker** = `DatabaseBackupService`（`listBackups()` 管理多个快照）+ `DatabaseRestore` 命令（`restore()` 恢复）

```php
// DatabaseBackupService::backup() —— 保存快照（Memento 的 createMemento）
public function backup(?array $tables = null, ?string $filename = null, ...): array
{
    // mysqldump 导出 → 生成备份文件
}

// DatabaseRestore::handle() —— 恢复快照（Memento 的 restore）
$result = $backupService->restore($filename, $tables);
// 先确认 "此操作将覆盖现有数据" 再执行 —— Caretaker 的安全护栏
```

关键点：**恢复前强制确认**（`$this->confirm(...)`）+ **可指定表**（部分恢复）——Caretaker 管理"何时恢复、恢复哪个、恢复多少"，但备份文件本身（Memento）不可变、不解析内部。

### 落点 ②：Amazon 商品快照（`amazon_product_snapshots` / `catalog_snapshots`）

更细粒度的 Memento：给商品的原始 JSON 打快照，用于**对比变化**：

```
RecordAmazonProductCatalogSnapshotsCommand   ← createMemento（记录快照）
DiffAmazonProductCatalogSnapshotsCommand     ← 对比最近两个快照（second-new → newest）
PruneAmazonProductCatalogSnapshotsCommand    ← Caretaker 清理旧快照
```

```php
// Diff...SnapshotsCommand：读取两个相邻快照做结构对比
$result = $diffService->diffLastTwoForProduct($product, ...);
```

这是 Memento 的进阶用法：**快照不只用于回滚，还用于"审计时间线"**（什么时候商品排名/内容变了）。`Diff` = 状态对比，`Prune` = 快照生命周期管理（Caretaker 职责）。

## 为什么重要

- **状态可回滚**：误操作、数据损坏时能恢复到快照点。
- **审计与对比**：快照时间线让"什么时候变的、怎么变的"可追溯（比只存最终状态强）。
- **不暴露内部**：快照是序列化产物，调用方不需要知道内部结构。
- **与审计日志的区别**：审计日志记录"操作事件"；Memento 快照记录"某个时刻的完整状态"。两者可互补。

## 怎么用 / 怎么实现（套路）

1. 确定"要被备份的状态"（整库 / 指定表 / 单对象 JSON）。
2. 写 `save()`（生成不可变快照：文件 / 快照表行）+ `restore()`（应用快照）。
3. 管理者（Caretaker）负责：列出快照、选恢复点、清理旧快照（`listBackups` / `Prune...Command`）。
4. 恢复是**破坏性操作**：必须确认 + 可审计。

## 易错 / 注意

- **恢复前必确认**：Memento 的 restore 会覆盖现状，Caretaker 要加护栏（`confirm`）。
- **快照有成本**：别对每次变更都打快照——用 `Prune` 命令按策略清理（只留最近 N 个）。
- **快照 vs 备份粒度**：整库备份（DatabaseBackup）和单对象快照（Amazon）是同一思想的两个尺度。
- **不要把 Memento 当唯一数据源**：快照是"还原点"不是"当前事实"，当前状态仍要正常持久化。
