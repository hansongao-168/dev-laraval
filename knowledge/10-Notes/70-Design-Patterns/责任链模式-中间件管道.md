# 责任链模式（Chain of Responsibility）：Laravel 中间件管道

## 一句话

> **责任链模式** = 把请求沿一条"处理者链"传递，每个处理者决定自己处理、转发给下一个，还是短路。**Laravel 中间件就是框架内建的教科书级责任链**，本仓库大量业务中间件都是这条链上的处理者。

## 是什么

### 责任链核心

```
Handler（处理者）
  ├── handle(request)：
  │     如果我能处理 → 处理并返回
  │     否则 → next(request)  // 传给链上下一个
  └── setNext(handler)         // 组装链
```

三个要点：
1. **每个处理者只关心自己那一环**（鉴权、限流、验证邮箱……）。
2. **处理者间解耦**：不知道下一个是谁，只知道"有 next 可传"。
3. **可动态组装、可短路**：`return $next($request)` 是"放行"；直接 `abort()` 是"短路"。

### 落点：Laravel 中间件管道（框架内建）

Laravel 的中间件签名就是责任链：

```php
public function handle(Request $request, Closure $next): Response
```

`$next` 就是"链上的下一个处理者"。本仓库用 `common` 的 `BaseMiddleware` 统一抽象：

```php
abstract class BaseMiddleware
{
    abstract protected function handle(Request $request, Closure $next, ...$params): Response;

    public function __invoke(Request $request, Closure $next, ...$params): Response
    {
        return $this->handle($request, $next, ...$params);   // 转发给链
    }
}
```

### 具体业务中间件（链上的各环）

| 中间件 | 职责 | 短路行为 |
|---|---|---|
| `EnsureEmailVerified` | 邮箱必须已验证 | `abort(403)` |
| `JwtAuthenticate` | JWT 鉴权 | 401 |
| `ApiScopeAuthorize` | API scope 授权 | 403 |
| `WarehouseOperator` | 仓库操作员权限 | 403 |
| `OptionalAuth` | 可选登录（有则解析，无则放行） | 不短路，降级为 guest |
| `ThrottleCustomerActions` | 客户操作限流 | 429 |
| `TrackLoginActivity` | 记录登录行为（后置） | 不短路 |

看 `EnsureEmailVerified` 的"我处理，否则转发"：

```php
public function handle(Request $request, Closure $next)
{
    $user = $request->user();
    if ($user === null) {
        abort(401, 'Unauthenticated');                 // 短路：链到此为止
    }
    if (! $user->hasVerifiedEmail()) {
        abort(403, '邮箱未验证');                        // 短路：链到此为止
    }
    return $next($request);                            // 放行：交给下一个处理者
}
```

`OptionalAuth` 是"不短路"的一环——它把请求放行，但把解析出的用户挂在 request 上，供下游使用。这就是责任链的灵活性：**每一环可以决定"拦/放/改"**。

## 为什么重要

- **横切关注点解耦**：鉴权、限流、验证、日志各自独立成环，增删一环不动其他环。
- **可组合、可复用**：同一中间件能挂到不同路由组；顺序即语义（鉴权要在授权前）。
- **框架内建**：不用自己造责任链，`withMiddleware()` 注册即可，框架负责组装。
- **与 Mediator 对比**：责任链是"请求沿链传递、处理者各管一段"；Mediator 是"中心协调、对象不直接互调"。

## 怎么用 / 怎么实现（套路）

1. 识别横切关注点（鉴权/限流/验证/日志）→ 每个一个中间件类。
2. 用 `handle($request, $next)`：需要拦截 → `abort()`/返回响应；需要放行 → `return $next($request)`。
3. 前置逻辑写在 `$next()` 前，后置逻辑写在 `$next()` 后。
4. 在 `bootstrap/app.php` 或路由 `->middleware()` 组装链，顺序即语义。
5. 需要统一抽象基类时，用 `BaseMiddleware`（`__invoke` 委托 `handle`）。

## 易错 / 注意

- **顺序敏感**：`auth` 必须在 `authorize` 前，`throttle` 在哪都行——链条顺序是语义的一部分。
- **别忘了 `return $next($request)`**：漏了 = 请求被吞掉，下游永远不执行。
- **后置逻辑**：写在 `$next()` 之后的代码是"响应回来后再跑"，注意别改已发出的响应。
- 责任链 vs 装饰器：两者都是"逐层包裹"，但责任链是**拦/放（决策）**，装饰器是**增强（处理）**。
