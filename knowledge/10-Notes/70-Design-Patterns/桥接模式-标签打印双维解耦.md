# 桥接模式（Bridge）：标签打印的"实体 × 输出"双维解耦

## 一句话

> **桥接模式** = 把"抽象"与"实现"两个维度拆开，各自独立演化，中间用桥（组合）连接，避免继承导致的类爆炸。`EntityBinderContract`（打印什么）× `LabelRendererContract`（怎么输出）= 教科书级桥接。

## 是什么

### 问题：打印标签的两个变化维度

- **维度 A（实体）**：给谁打印？库存商品（InventoryProduct）、库存转移单（InventoryTransfer）、库位（WarehouseLocation）……以后还会加。
- **维度 B（输出）**：用什么格式输出？浏览器 HTML、PDF、ZPL 热敏……以后还会加。

如果用继承硬编码：`InventoryProductPdfRenderer`、`InventoryProductBrowserRenderer`、`TransferPdfRenderer`……**实体数 × 格式数 = 类爆炸**（3×2=6 起，每加一维乘一次）。

### 解：两棵独立接口树 + 桥

```
实体维度（Binder）                    输出维度（Renderer）
EntityBinderContract               LabelRendererContract
  ├─ InventoryProductBinder          ├─ BrowserLabelRenderer
  ├─ InventoryTransferBinder         └─ (未来) PdfLabelRenderer / ZplRenderer
  └─ WarehouseLocationBinder

              ▲                          ▲
              └───────── 桥 ─────────────┘
        LabelTemplateRendererOrchestrator（持有 binder + renderers 注册表）
```

新增实体 → 只加一个 Binder；新增输出 → 只加一个 Renderer。**两个维度互不感知**，组合在 Orchestrator 里。

### 实体维度的 Binder（`LabelDataBinder` 门面 + 各 Binder）

```php
class LabelDataBinder
{
    /** @param array<string, EntityBinderContract> $binders */
    public function __construct(private readonly array $binders) {}

    public function load(LabelEntityType $entityType, array $ids): array
    {
        return $this->binder($entityType)->load($ids);   // 按实体类型选 Binder
    }
}
```

`InventoryProductBinder`/`InventoryTransferBinder`/`WarehouseLocationBinder` 各实现 `EntityBinderContract`（`entityType/modelClass/load/sample`），把"怎么取某实体的字段"封装在各自类里。

## 为什么重要

- **消除类爆炸**：实体数 + 输出格式数，而不是乘积。
- **两维独立演化**：加 PDF 渲染器不需要碰任何 Binder。
- **与策略的区别**：策略是"同维度换算法"；Bridge 是"两个不同维度正交组合"。这里 Binder 与 Renderer 是**正交**的（每种实体 × 每种格式都能组合），所以是 Bridge 不是 Strategy。

## 怎么用 / 怎么实现（套路）

1. 识别两个正交的变化维度（这里是"数据源"和"输出格式"）。
2. 每个维度定义一个接口（`EntityBinderContract` / `LabelRendererContract`）。
3. 各写具体类，实现各自接口，互不依赖对方维度。
4. 建一个"桥"类（`LabelTemplateRendererOrchestrator`）持有两维的注册表，负责组合。
5. 容器按接口聚合注入所有实现。

## 易错 / 注意

- **别把 Bridge 写成策略**：如果两个"维度"实际是"同一件事的不同算法"（如多种排序），那是 Strategy。
- 桥接后的组合要**正交可行**：不是所有 实体×格式 都有意义（如"库位 × 3D 打印"），用注册表 + 缺失时报错（`No renderer registered`）兜底。
- 注册表是 `array<string, class>`，键是枚举 value——**枚举值改名会破坏映射**。
- 判断标准：会不会出现"N×M 个类"的冲动？会 → 该用 Bridge。
