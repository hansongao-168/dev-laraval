# 组合模式（Composite）：导航树与标签模板的"整体-部分"

## 一句话

> **组合模式** = 让"单个对象"和"对象组合"用**同一接口**处理，客户端不用区分叶子还是树枝。本仓库的导航树（`NavItem.children`）和标签模板（`LabelTemplate.elements`）都是树形整体-部分结构的实例。

## 是什么

### 经典结构

```
Component（统一接口）
  ├── Leaf（叶子：没有子节点）
  └── Composite（容器：含多个 children，操作会递归到子节点）
```

客户端对 Leaf 和 Composite **一视同仁**，递归调用无需类型判断。

### 本项目落点 ①：导航树（`NavItem` + `NavNormalizer`）

`NavItem` 本身就是一棵"整体-部分"树：

```php
final class NavItem
{
    public ?string $parent;      // 指向父节点 key
    // children 由 NavNormalizer::toTree() 从 parent 指针重建
}

// NavNormalizer::toTree() 把扁平列表按 parent 组装成 2 层树
foreach ($items as $item) {
    if ($item->parent !== null && isset($byKey[$item->parent])) {
        $children[$item->parent][] = $item;   // 挂到父节点下
        continue;
    }
    $topLevel[] = $item;                      // 无 parent = 顶级
}
```

**统一处理**体现在两处：
1. **递归装饰**（`packages/front-nav` 的 `resolveLabels`）：叶子也翻译、树枝也翻译、子树的子树也翻译——递归调用，Leaf 与 Composite 用同一函数处理。
2. **统一序列化**：`toArray()` 每个节点都带 `children`（空数组也算叶子），前端不区分层级。

### 本项目落点 ②：标签模板树（`LabelTemplate` → `LabelTemplateElement`）

```
LabelTemplate（Composite：标签整体）
  └── LabelTemplateElement（Leaf：单个元素，Text/Barcode/QrCode/Image/Line/Rectangle）
```

```php
public function elements(): HasMany
{
    return $this->hasMany(LabelTemplateElement::class)->orderBy('z_order');
}
```

`LabelElementBinder::render()` 对每种元素类型用同一入口（`match ($element->type)`）渲染——客户端（`BrowserLabelRenderer`）只需遍历模板的 elements，逐个调用 binder，**不用关心元素内部结构**。

### 与 Composite 的异同

| 维度 | 导航树 | 标签模板树 |
|---|---|---|
| 结构 | 深度不固定（2 层封顶） | 固定 2 层（模板→元素） |
| 节点类型 | 单一 `NavItem` | `LabelTemplate`（父）+ `LabelTemplateElement`（子） |
| 处理方式 | 递归（resolveLabels / toArray） | 遍历 + match 分派 |
| 模式纯度 | 更像"树形数据 + 递归处理" | 更接近经典 Composite（父-子异构） |

**结论**：导航树体现 Composite 的**递归统一处理**思想；标签模板是**父-子异构**的经典 Composite。两者都不算"满血"GoF Composite（接口完全统一），但都踩在"整体-部分统一对待"的核心上。

## 为什么重要

- **客户端免判型**：前端渲染导航、打印标签时无需 `if (isLeaf) ... else ...` 的分支。
- **递归天然适配树**：装饰、序列化、渲染都能用一次递归搞定。
- **数据模型直观**：DB 用 `parent` 指针 / `z_order` 排序表达层级，无冗余。

## 怎么用 / 怎么实现（套路）

1. 数据模型：父表 + 子表（或单表自引用 `parent` 字段）。
2. 组装：一次遍历把扁平数据建树（`NavNormalizer::toTree`）。
3. 消费：递归函数统一处理节点（`resolveLabels` / `toArray`）。
4. 需要"节点行为随类型变"时：配合策略/工厂分派（`LabelElementBinder` 的 `match`）。

## 易错 / 注意

- **别把树建在查询里循环**：N+1 查询。一次查出全部再内存建树（`NavNormalizer` 就是两次循环 O(n)）。
- **递归要防环/防深**：parent 指回自己或过深会栈溢出；本项目用"孤儿提升到顶级"兜底。
- 层级是否封顶要看业务：导航 2 层封顶是刻意设计，不是没做完。
