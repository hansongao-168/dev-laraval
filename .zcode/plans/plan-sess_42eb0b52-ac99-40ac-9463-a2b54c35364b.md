## 目标

在 `gz168/DatabaseManager` 下面新建一个独立的「多数据库管理」模块：
- 可在线登记多个数据库连接（MySQL），密码用 `Crypt` 加密落库。
- 可在某个连接下选择多个表做结构/数据/全量备份，可按整库或子集还原。
- 提供「连接间导入导出」（源连接 → 目标连接，整库或子集 + scope）。
- 提供「定时策略 UI」：全局默认 + 每个连接覆盖（cron 表达式 + 保留期）。
- 保留现有 `gz168/DatabaseBackup` 不破坏（旧模块标 deprecated，保留旧备份文件可继续被旧命令恢复）。

## 默认假设（如果你的答案不同，告诉我后会调整）

1. 旧模块迁移策略：**新建独立模块 + 旧模块标记 deprecated**（选项 1，最安全）。
2. 「跨连接多表聚合」范围：**同逻辑表跨多连接**（选项 1，即"按连接分别产出备份"），不做"合并单文件"那种高风险版本。
3. 「连接间导入导出」：**全库复制 + 选定表子集复制 + 上传 .sql.gz 到任一目标连接**（三个都做）。
4. 「定时策略 UI」：**全局默认 + 每连接覆盖**（选项 1）。
5. 「压缩/分卷/云上传」本期只做：保留 gzip + 可选 split 卷；云上传作为**下一期**，本期不接（依赖 s3 驱动 + 凭据，留给后续 story）。
6. 还原模式：**默认走异步 Job**（参考 AmazonProductImportJob 的「DB row 状态 + Filament 轮询」模式），小表阈值内可同步；这样不破坏现有 HTTP 超时模型。

## 关键设计

### 1. Connection 模型 + Crypt
直接复制 `RedisInstance` 的 `setPasswordAttribute/getPasswordAttribute`。密码字段为 `text`，空串/null 落库为 null。

### 2. 临时连接解析（核心难点）
Laravel 的 DB facade 不会在运行时去找新连接的密码。我们写一个 `DatabaseConnectionResolver`：

```
public function makeConfig(DatabaseConnection $c): array
{
    return [
        'driver' => 'mysql',
        'host' => $c->host,
        'port' => $c->port,
        'database' => $c->database,
        'username' => $c->username,
        'password' => $c->password,  // accessor 已解密
        'charset' => $c->charset,
        'collation' => $c->collation,
        'prefix' => $c->prefix ?? '',
        'strict' => true,
        'engine' => null,
        'options' => $c->options_json ?? [],
    ];
}
```

调用方式：`DB::purge('dm_'.$conn->id); Config::set('database.connections.dm_'.$conn->id, $resolver->makeConfig($conn));` 然后 `DB::connection('dm_'.$conn->id)` 使用。purge 避免连接缓存。

### 3. BinaryResolver 复用
直接复制 `gz168/DatabaseBackup/src/Services/BinaryResolver.php`，**先不抽公共**（避免触动其它模块）。重复属于技术债，但本期收敛。后续可在 `gz168/common` 提取。

### 4. 备份/还原命令构造
保留现有 `buildDumpCommand/buildRestoreCommand` 的结构，但 `getDatabaseConfig()` 改为接收 `DatabaseConnection` 实例。命令字符串构造继续用 `Process::fromShellCommandline()`，加密字符已脱敏（`escapePassword` 同款保留）。

### 5. 异步 Job 与进度
新模块参照 `AmazonProductImportJob`：
- 入口（手工按钮 / artisan / 定时）：创建 `DatabaseBackup` row（status=pending），把 `uuid` 返回给前端/控制台，立即 dispatch Job。
- `RunDatabaseBackupJob` 把 status=processing，每写入一张表 → 更新 `progress_message` + `progress_pct`（按表数平均），写入 `meta_json.progress`。
- 完成/失败 → 写入 status/completed_at/failed_at/error_message。
- 失败有 `failed()` 钩子，类似 Amazon。
- Job 配置：`tries=3`、`backoff=[30,60,120]`、`timeout=3600`（大库 1 小时超时）。
- 进度展示：Filament View 页面用 Livewire `wire:poll.2s` 轮询该 row。

### 6. 跨连接迁移
- 表单：源连接 + 目标连接 + 表子集 + scope + 预备份开关。
- 行为：先在源连接 mysqldump（自动 Job）落一份临时 `database_backups` 文件；然后在目标连接 mysql 还原；过程写一张 `DatabaseBackup` row，operation=transfer。
- 全程不需要合并文件，复用 dump/restore 命令即可。

### 7. 定时策略 UI（DatabaseSchedulePage）
- 表单：默认 cron（如 `0 2 * * *`）、默认保留份数（如 30）、是否启用、是否预备份。
- DatabaseConnection 编辑表单加两个字段 `schedule_cron`、`retention_count`（覆盖默认）。
- `DatabaseManagerServiceProvider::boot()` 在 `runningInConsole()` 里遍历所有 active 连接 + 全局默认，逐条 `Schedule::command('db-manager:backup --connection={id}')->cron($cron)->onOneServer()->withoutOverlapping()`。

### 8. Filament 页面
- **DatabaseConnectionsPage** 列出所有连接 + `Create/Edit/Delete` 按钮 + 测试连接按钮。CRUD 用 Resource 做（Country 模板）。
- **DatabaseBackupsPage** 用 `HasTable` + `InteractsWithTable`（DatabaseBackupPage 模板），按连接筛选；行操作：还原（弹窗确认 scope/表）、下载（Response::download）、删除（删除磁盘文件 + 数据库 row）。
- **DatabaseSchedulePage** 一个简单 Form（不需表格），保存后即时刷新 Schedule。
- 全部走 `Authorizable::hasPermission()` 守卫，新注册 slug：`database-manager.view / .create / .edit / .delete / .test / .backup / .restore / .transfer / .schedule / .upload`。
- 注册方式：**新增 `gz168/DatabaseManager/database/seeders/DatabaseManagerPermissionSeeder.php`，由 DatabaseManagerServiceProvider 在 boot 里调用 `php artisan db:seed --class=...` 的等价方式**（或在 ServiceProvider 的 `packageBooted` 里手动注册 `Permission::firstOrCreate([...])`）—— 这样不动中央 `PermissionSeeder`，与 ModuleSettings 模式一致。

### 9. 与 gz168/DatabaseBackup 的关系
- 不删除、不修改旧模块。
- 在 `DatabaseBackupPage` 的 Blade 视图顶部加一个 `\Filament\Notifications\Notification`-风格的横幅：「新版多数据库管理已上线：[跳转]」+ 一行"本页保留旧版单库备份，仅用于旧备份文件还原"。
- 旧备份文件保留在 `storage/app/backup/`；新备份默认在 `storage/app/private/database-manager/{connection_id}/{YYYY}/{MM}/`（每连接独立目录，便于按连接清理）。
- DatabaseBackupServiceProvider 不动。新模块独立注册 schedule。

手工验证（必须人工，无法 e2e）：
1. `/admin/database-connections` 创建一条 MySQL 连接。
2. 点击「测试连接」通过。
3. `/admin/database-backups` 选该连接 + 单表 + scope=data → 触发备份 → 等 Job 完成 → status=completed，文件出现在 `storage/app/private/database-manager/{cid}/.../*.sql.gz`。
4. 选中该备份 → 还原到原连接（先备份再 truncate 再灌入）→ 成功。
5. 新建第二条连接 → 跨连接迁移（源→目标）→ 成功。
6. 在 `/admin/database-schedule` 启用 + cron 写 `*/5 * * * *`（测试用）→ 5 分钟后该连接出现一条 `auto_*.sql.gz` 备份。
7. 关闭连接 `is_active=false` → schedule 不再调度该连接。

- 真正的云上传（s3/COS 落地）—— 留接口 `disk` 字段已加，后续补 `BackupDestination` UI + driver。

- 加密备份（AES）—— 不在需求中。
- 从旧 `gz168/DatabaseBackup` 导入历史备份到新模块 —— 可后续做一次性导入脚本。
- 实时大屏轮询（websocket）—— Livewire `wire:poll` 已经够用。
