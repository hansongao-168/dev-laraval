## gz168 零耦合改造执行计划

### 目标

让 `gz168` 模块化系统成为**完全可选、可独立运行**的扩展：
- 主项目 `composer install` **零 gz168 依赖**
- 默认 `php artisan` 命令**不依赖 gz168**
- 通过 `php bin/install-gz168.php` 一键启用
- gz168 模块代码**完全不引用** `App\` 命名空间

### 完整执行步骤

#### Phase A：主项目去除硬编码 Provider 注册

**修改 `bootstrap/providers.php`**：删除 `Gz168\FilamentAdmin\Panels\AdminPanelProvider` 与 `Gz168\ModuleCore\ModuleCoreServiceProvider` 两行。

理由：Laravel 13 的 `extra.laravel.providers` 自动发现机制已生效（确认 `bootstrap/cache/packages.php` 第 191-197 行已缓存这两条记录）。移除硬编码后，只要 `composer require gz168/*`，Service Provider 仍会注册。

#### Phase B：清理根 `composer.json`

**修改根 `composer.json`**：
- 删除全部 22 个 `gz168/*` require
- 删除全部 22 个 path repositories
- （保留 `filament/filament`、`laravel/framework`、`laravel/sanctum` 等非 gz168 依赖不动）

#### Phase C：gz168 模块启动条件化

**新建 `gz168/module-core/src/Support/EnabledChecker.php`**：
- 检查 `config('module-core.enabled', false)` 或 `env('GZ168_ENABLED', false)`
- 返回 `bool`

**修改 `gz168/module-core/src/ModuleCoreServiceProvider.php`**：
- `boot()` 顶部增加 `EnabledChecker` 判断
- 未启用时直接 `return`，不扫描、不加载

**修改 `gz168/module-core/config/module-core.php`**：
- 增加 `'enabled' => env('GZ168_ENABLED', false)` （默认 false）

#### Phase D：修复 11 处反向依赖

依据 Explore 报告的精确清单：

**D.1 在 `common` 模块新建 4 个契约文件**：
- `common/src/Http/Controllers/ApiController.php` —— 抽象基类，继承 `Illuminate\Routing\Controller`
- `common/src/Contracts/Authenticatable.php` —— 用户模型契约接口
- `common/src/Support/SensitiveValueMasker.php` —— 脱敏服务（从 ModuleSettings 提升）
- `common/src/Support/PathHelpers.php` —— 模块路径解析

**D.2 替换 `use App\Http\Controllers\Controller`（4 处）**：
- `UserManagement/src/Http/Controllers/Api/Admin/UserController.php:5`
- `UserManagement/src/Http/Controllers/Api/CustomerController.php:5`
- `UserManagement/src/Http/Controllers/Api/Front/UserController.php:5`
- `ModuleSettings/src/Http/Controllers/PublicModuleSettingController.php:5`

→ 改为 `use Gz168\Common\Http\Controllers\ApiController;`

**D.3 替换 `use App\Models\User`（5 处）**：
- `ApiAuth/src/Models/RefreshToken.php:5` —— `user()` relation 改用 `config('auth.providers.users.model')`
- `ApiAuth/src/Models/ApiClientCredential.php:5` —— `user()` / `approvedBy()` 同上
- `ApiAuth/src/Services/TokenService.php:5` —— `resolveUser()` 等改用配置
- `UserManagement/src/Filament/Resources/UserResource/UserResource.php:9` —— 改用 `UserManagementModels::user()`
- `UserManagement/src/Support/UserManagementModels.php:12` —— `\App\Models\User::class` 改为 `config('auth.providers.users.model')`

**D.4 修复 filament-admin（1 处）**：
- `AdminPanelProvider.php:43,53,66` 的 `app_path('Filament/...')` 三处 → 删除（主项目若要扩展面板自己注册）
- `OdooSettings` 与 `DashboardStatsWidget` 反向 `use` → 暂保留但加注释说明应迁移

#### Phase E：安装/卸载脚本

**新建 3 个 CLI 工具**：

**`bin/install-gz168.php`**：
- 默认安装 8 个核心模块（`module-core common filament role-permission user-management api-auth extension-data export-management`）
- 支持 `--interactive` 交互式选择
- 自动更新 `composer.json`（添加 path repositories 和 require）
- 自动添加 `GZ168_ENABLED=true` 到 `.env`
- 执行 `composer update`

**`bin/uninstall-gz168.php`**：
- 支持 `--all` 全部卸载或指定模块别名
- 从 `composer.json` 删除对应 require 和 repositories
- 设置 `GZ168_ENABLED=false`
- 执行 `composer update`

**`bin/check-gz168-coupling.php`**：
- 扫描 `gz168/*/src/**/*.php`
- 检测 4 类违规：
  1. `use App\` 语句
  2. `App\Models\User` 硬编码字符串
  3. `app_path('Filament/...')` 调用
  4. `\App\Models\User::class` 字面量
- 返回非零退出码以便 CI 拦截

#### Phase F：环境与文档

**修改 `.env.example`**：增加
```
# gz168 modules (disabled by default)
GZ168_ENABLED=false
GZ168_MODULES_PATH=gz168
```

#### Phase G：最终验收

执行以下命令验证：
```bash
# 1. 验证主项目零 gz168 引用
grep -c "gz168" composer.json              # 期望: 0
grep -c "Gz168" bootstrap/providers.php    # 期望: 0

# 2. 验证 gz168 零反向依赖
php bin/check-gz168-coupling.php           # 期望: ✅ gz168 has zero coupling with main app

# 3. 验证 ModuleCore 启动条件化
GZ168_ENABLED=false php -r "require 'vendor/autoload.php'; (new Laravel\Foundation\Application)->boot();" # 不报错

# 4. 验证 install 脚本
php bin/install-gz168.php --interactive    # 期望: 提示选择并安装
php artisan module:list                    # 期望: 列出已启用模块

# 5. 验证 uninstall 脚本
php bin/uninstall-gz168.php --all         # 期望: 还原
```

### 风险与约束

1. **`UserResource.php` 改用 `UserManagementModels::user()` 后类型提示变化** —— Filament Resource 的 `form()` 中 `User $record` 类型提示需改为 `Model` 或动态类型
2. **`TokenService::resolveUser()` 返回类型从 `User` 改为动态** —— PHPStan 可能抱怨，需用 PHPDoc 注明 `@var Authenticatable`
3. **`bootstrap/cache/packages.php` 缓存** —— 修改 `composer.json` 后需 `composer dump-autoload` 刷新
4. **测试需配合更新** —— UserManagement/ApiAuth 的测试中 `App\Models\User` 引用需同步替换

### 执行顺序

1. Phase A → B → C（主项目侧去耦合，先让项目能独立运行）
2. Phase D（gz168 内部修复反向依赖）
3. Phase E → F（脚本与配置）
4. Phase G（验收）

每个 Phase 内独立、可单独验证。失败可回退到上一 Phase。
